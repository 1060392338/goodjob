# ADR-0006：线索外联幂等与跨聚合转化边界

- 状态：Accepted
- 日期：2026-07-14
- 关联：`REQ-GJ-ARCH-001 / TASK-GJ-0003 / L-0007`
- 依赖：`ADR-0005`

## 背景

线索社交触达、邮件发送、转化预览和转客户/商机 4 个接口仍内联在 `server.ts`。其中邮件发送包含 SMTP 外部副作用，线索转化同时写入线索、客户、商机、商机事件和线索活动。直接搬迁会保留以下风险：重复请求可能重复发送或重复写入；SMTP 超时后的结果不确定；持久化失败可能留下内存中的半完成聚合；领域代码继续依赖 Nodemailer。

## 决策

1. 4 个接口保持 URL、HTTP 方法、输入、既有状态码、权限范围和成功响应兼容，迁入独立的线索外联与转化路由模块。
2. SMTP 只能通过 `OutboundEmailGateway` 接入。领域与路由测试使用 Mock Gateway，不连接真实 SMTP。
3. 外联请求使用可选 `Idempotency-Key`。服务端只保存键的哈希和请求载荷哈希，不保存原始键；相同用户、线索、动作和键：
   - 已成功请求返回原结果且不得再次发送/写活动；
   - 相同键但不同载荷返回冲突；
   - `pending` 或结果不确定的请求不得自动重放；
   - 未提供键时生成一次性请求标识，保持旧客户端兼容。
4. 新增 `lead_outreach_requests` 持久化记录，保存动作、渠道、状态、活动引用、外部消息 ID、公开错误和时间，不保存邮件正文、SMTP 凭证或原始幂等键。
5. 邮件发送先持久化 `pending` 请求，再执行 Gateway；发送成功后在同一次持久化中写入活动、用户发送摘要、线索状态和成功记录。若最终持久化失败，内存状态回滚为 `pending`，避免自动重复发送。
6. 社交触达接口继续表示“人工触达记录”，不声称已经调用 WhatsApp、LinkedIn、微信或电话平台。真实平台发送必须在阶段 6 通过 Collaboration Adapter 实现。
7. 线索转化由领域服务协调线索、客户、商机、商机事件和活动。持久化失败时回滚本次内存变更；已转化线索继续通过 `convertedCustomerId/convertedDealId` 幂等返回。
8. 客户/商机来源仍通过保留的线索及 `leadSourceEvents` 反查，本循环不复制或删除来源事件。

## 验收

- 无权访问、已删除线索不得触达、发邮件、预览或转化；
- 邮件 Gateway 失败与超时不生成成功活动；
- 相同幂等键不重复调用 Gateway，不重复生成活动；
- 重复转化不重复创建客户、商机和事件；
- 转化持久化失败后线索、客户、商机、事件和活动恢复到调用前状态；
- OpenAPI/注册操作继续保持 167，security、verify 与 E2E 门禁通过。

## 回滚

代码回滚时撤销 L-0007 路由装配并恢复 `server.ts` 内联实现。`lead_outreach_requests` 表为追加式兼容表，回滚代码不要求删除表；如需物理删除必须先确认无审计/幂等记录保留要求并单独执行受控迁移。

## 后果

- 邮件副作用具备可测试 Gateway 和持久化幂等边界；
- `pending` 请求可能需要后续运维查询/人工确认，不能在结果不确定时自动重发；
- 当前 Store 仍采用整体快照持久化，进程内回滚不能替代数据库级细粒度事务，阶段 7 需继续演进 Repository/Unit of Work。
