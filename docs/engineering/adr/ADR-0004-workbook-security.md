# ADR-0004：工作簿依赖与安全边界

- 状态：Accepted
- 日期：2026-07-13
- 关联：`REQ-GJ-SEC-002 / TASK-GJ-0004`

## 背景

前端直接依赖 npm Registry 中的 `xlsx@0.18.5`，依赖审计报告 Prototype Pollution 与 ReDoS 两个 High 漏洞，且 npm Registry 没有可自动升级的修复版本。当前系统同时使用 XLSX、旧版 XLS 与 CSV 的读取能力，并有客户、题库、提成、搜客等多个导入导出流程。

## 决策

1. 按 SheetJS 官方安装文档，将依赖升级到官方 CDN 发布的 SheetJS CE `0.20.3` tarball；锁文件记录版本、来源和完整性摘要。
2. 不在业务大文件中直接处理不可信工作簿；新增统一工作簿边界模块，集中执行扩展名、文件大小、行数、列数、单元格长度和危险表头校验。
3. 读取结果使用无原型对象，拒绝 `__proto__`、`prototype` 和 `constructor` 等危险表头，避免业务映射继承意外属性。
4. 保留 XLSX、XLS、CSV 三类现有导入兼容；所有新增工作簿能力必须通过统一模块。
5. 增加恶意表头、超限文件、超限行列和兼容回归测试；依赖审计 High/Critical 必须为 0。

## 未选择方案

### ExcelJS

优点是 npm 分发稳定、API 清晰且适合 XLSX 写入；但本项目现阶段仍声明支持旧版 `.xls` 导入，ExcelJS 不提供等价的旧版 XLS 读取能力。立即切换会造成兼容回归并扩大五处导出和两处导入的改造范围，因此本循环不采用。

### 继续使用 npm Registry 的 `xlsx@0.18.5`

已知 High 漏洞无可用修复，不能作为内部正式版依赖，拒绝继续使用。

### 只靠文件大小限制

文件大小限制不能处理原型污染和畸形内容，必须同时升级依赖并进行结构校验。

## 后果

- 保持现有 SheetJS API 和 XLS/XLSX/CSV 行为，降低业务回归风险。
- 安装依赖新增 SheetJS 官方 CDN 可用性要求；锁文件完整性用于防止内容漂移。
- 后续若取消旧版 XLS 支持，可重新评估 ExcelJS 或服务端流式处理方案。
